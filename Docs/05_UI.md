# 05 — Menu and HUD contract

Implemented in `Assets/PixelArena/Scripts/UI/PixelArenaUI.cs`. The UI is a self-bootstrapping runtime IMGUI component; it does not require a Canvas, scene object, prefab reference, or scene modification. It is created before the first scene loads and survives scene changes.

## Menu and network flow

- The menu binds to `NetworkManager.singleton` when it is a `NetManager`. Until task 06 adds the configured network root, it displays an explicit integration message instead of creating a competing manager.
- **Host** calls `NetManager.StartHost()`. **Connect** applies the entered direct/LAN address to `networkAddress` and calls `StartClient()`. **Dedicated Server** calls `StartServer()`.
- After a client connection succeeds, **Play / Find Match** calls `NetManager.ClickJoinRoom()`. Loading, matchmaking, leaving and errors are shown from `ClientPhase` and `StatusText`.
- **Retry Match** retries `ClickJoinRoom()` while the transport remains connected. **Retry Last Connection** repeats the last host/server/client start after stopping an active transport. Connection exceptions are shown and logged.
- **Leave Match** calls `ClickLeaveRoom()` and keeps the transport connection, matching the networking contract. **Disconnect / Stop Host / Stop Server** invokes the appropriate Mirror stop method.
- Escape is handled by `PlayerMotor`, which releases the cursor. The pause panel resumes through `PlayerMotor.SetLocalInputEnabled(true)`, leaves the room, or stops the connection. Menus always release and show the cursor.

The UI never sends room messages directly, creates network objects, or changes replicated match state.

## HUD data sources

While `NetManager.ClientPhase == MatchPhase.Playing` and a local player exists, the UI reads only public replicated/presentation APIs:

- `PlayerCombat`: HP/max HP, death state, selected weapon name, magazine/reserve, reload state and progress.
- `PlayerMotor.GetInteractionPrompt()`: locally queried E prompt, refreshed at 10 Hz while gameplay input is active. Server interaction validation remains in `PlayerMotor` and the target.
- `NetManager.KillFeedReceived`: room-filtered entries retained for six seconds, with local player IDs rendered as `You`.
- `BunkerController.Local`: ready/countdown/cooldown state, door state and `RemainingSeconds`. Countdown and cooldown are rendered as `MM:SS` using the replicated `NetworkTime` deadline.

The HUD also draws a center crosshair, HP bar, weapon/ammo block, reload bar, respawn message and up to six kill-feed entries. It scales from a 1920 × 1080 virtual layout using the smaller screen axis.

## Task 06 integration

No UI wiring is required. Add the configured `NetManager` root and player/match prefabs described by tasks 01–04. `PixelArenaUI` will discover them at runtime. Do not add a second `PixelArenaUI`; its bootstrap keeps a single persistent instance.

The runtime UI uses Unity IMGUI intentionally for this MVP. It has no external font, TextMeshPro, UI Toolkit, EventSystem or input-module dependency, which keeps host, client and dedicated-server setup identical. A later art pass can replace the renderer while keeping the same public data sources and commands.

## Checks and limitations

- Script was authored/imported through MCP for Unity against `Pixel Arena@1e4793473d861000`.
- Unity compilation completed with no C# errors. Script validation reported no errors.
- Two Play Mode smoke-test attempts were stopped after the Editor remained in `playmode_transition`; the runtime bootstrap could not be inspected through MCP. No C# runtime errors were logged during either attempt. This is not counted as a passing gameplay test.
- The current SampleScene does not yet contain the configured network root, so complete host/client navigation and live replicated HUD behavior remain for tasks 06 and 07.
- Player names do not exist in the current networking contract. Kill feed therefore uses Mirror net IDs (`Player 12`) and `You` for the local identity.
- This is direct-address/LAN UI. It does not claim relay, NAT traversal, authentication, public server discovery or cloud hosting.
